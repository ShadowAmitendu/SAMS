# Security Policy

## Supported Versions

The following versions of SAMS are currently supported with security updates.

| Version | Supported |
| ------- | --------- |
| 1.x.x   | :white_check_mark: |
| < 1.0   | :x:        |

> **Note:** Security support is provided for the latest stable release. Older versions may not receive security patches.

## Reporting a Vulnerability

The security of SAMS and the privacy of its users are important.

If you discover a security vulnerability, please report it responsibly rather than publicly disclosing it.

### How to Report

- **GitHub:** Open a private security advisory through the repository's Security tab using [Report a vulnerability](../../security/advisories/new).
- **Email:** Contact the project maintainers through the security contact email listed in the repository.

Please include the following information in your report:

- A clear description of the vulnerability.
- Steps to reproduce the issue.
- Potential impact and affected components.
- Screenshots, logs, or proof-of-concept code, if applicable.

### Response Timeline

We aim to follow these response guidelines:

| Activity | Expected Timeline |
| -------- | ----------------- |
| Initial acknowledgement | Within 72 hours |
| Initial assessment | Within 7 days |
| Status updates | As necessary |
| Security fix | Depending on severity and complexity |

These timelines are targets and may vary depending on the nature of the reported vulnerability.

### What to Expect

- **Accepted vulnerabilities:** The issue will be investigated, prioritized, and addressed through an appropriate security patch or release.
- **Declined reports:** If a report is not considered a security vulnerability, the reporter will receive an explanation where possible.
- **Responsible disclosure:** Reporters are requested to allow reasonable time for investigation and remediation before publicly disclosing the vulnerability.

### Scope

Security reports may include vulnerabilities related to:

- Authentication and authorization.
- Student and faculty data exposure.
- Unauthorized attendance modification.
- QR code generation and verification.
- Session and access control.
- SQL injection and other database vulnerabilities.
- API security and privilege escalation.
- Sensitive information disclosure.

Thank you for helping keep SAMS secure.
